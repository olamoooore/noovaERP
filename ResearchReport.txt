Basic QA Terms I Must Know
Test Case: A step-by-step check to confirm whether a function works.
Expected Result: What should happen if the system is correct.
Actual Result: What actually happens during testing.
Pass: The actual result matches the expected result with evidence.
Fail: The feature exists but behaves wrongly.
Blocked: The test cannot continue because something required is missing or broken.
Not Testable: The result cannot be verified with the current access, system, or environment.
Evidence: Proof such as screenshots, API response, document number, journal entry, dashboard value, report result, database record, or audit trail.
Bug / Defect: A problem where the actual result is different from the expected result.
Retest: Testing again after the engineer says an issue has been fixed.
Regression Test: Checking that old working features did not break after a fix.
Basic System Understanding
Frontend: What the user sees in the browser.
Backend: The system logic behind the screen.
API: The connection between frontend and backend.
Database: Where system records are stored.
Ledger / Journal Entry: Accounting record created after posting.
Dashboard: Summary numbers from system records.
Report: Formal output such as Trial Balance, General Ledger, AR/AP report, or tax report.
