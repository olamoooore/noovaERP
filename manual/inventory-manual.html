NoovaERP User Manual

Inventory Module

This manual is aligned to the current inventory routes, forms, statuses, and stock rules in the live NoovaERP codebase. It avoids assumed workflows and focuses on what the module actually exposes today.

/inventory and /inventory/* Warehouse-based stock control Direct stock entry depends on SME Mode

Scope

The current inventory module is built around these user surfaces: the overview dashboard, stock management, stock operations, purchase orders, warehouse transfers, warehouse setup, supplier setup, and inventory settings.

The module also has backend rules that matter to operators and administrators: warehouse stock is the real operational stock source, stock mutations are funneled through a single inventory service, and formal financial-impact flows must stay aligned with accounting.

Read This First

If you need direct manual stock entry, check /inventory/settings first. When SME Mode is turned off, the separate Stock Operations page intentionally blocks direct stock entry and tells users to use the purchase-order workflow instead.

Current Routes

The main app routes currently wired for inventory are listed below.

/inventory

Inventory overview dashboard with KPI cards, quick actions, low-stock preview, and recent stock movements.

/inventory/stock

Stock Management page with the Products, Movements, Low Stock, and Out of Stock tabs.

/inventory/operations

Dedicated Stock Operations page for Receive Stock, Remove Stock, and Count Stock.

/inventory/purchase-orders

Purchase order list with search, status filter, and document navigation.

/inventory/purchase-orders/new

Create a new purchase order with supplier, warehouse, dates, notes, and item rows.

/inventory/transfers

Warehouse transfer list with search, status filter, and transfer actions.

/inventory/transfers/new

Create a warehouse-to-warehouse transfer request.

/inventory/warehouses

Create, edit, search, and review warehouse cards and warehouse-level metadata.

/inventory/suppliers

Manage supplier records, contact data, commercial details, ratings, and notes.

/inventory/settings

Inventory behavior settings including SME Mode, stock rules, and SKU generation.

Inventory Overview

The overview dashboard is the fastest place to judge stock health before opening the detailed pages.

Total Products

Shows the active inventory item count returned by the inventory dashboard summary.

Warehouses

Shows how many warehouse records are currently configured and links into warehouse management.

Low Stock / Out of Stock

Shows alert counts from the dashboard summary. These counts are the authoritative card totals used by the current UI.

Value Cards

The dashboard also shows stock value at cost, retail value, and potential profit. These are overview numbers designed for monitoring, not transaction entry.

Quick Actions

  • Stock In and Stock Out quick actions currently route users into /inventory/stock.
  • Transfer Stock opens /inventory/transfers/new.
  • Purchase Order opens /inventory/purchase-orders/new.

Preview Areas

  • Low Stock Alert shows a short preview list of low-stock items, with a View all link back to stock management.
  • Recent Stock Movements shows the latest inventory changes and their movement type badges.
  • Module Navigation gives quick access to suppliers, warehouses, and other inventory pages.

What Adjust Means Here

The current UI describes Adjust as reconciling the recorded quantity to the counted quantity. Use it when the system balance must be reset to a verified physical count.

Stock Operations

The separate Stock Operations page at /inventory/operations is focused on manual stock events rather than stock review.

Tabs on This Page

Tab Use it for Key fields

Remove Stock Manual removals from stock. Product, warehouse, quantity, reason, reference, notes.

SME Mode Gate

If SME Mode is turned off, this page shows a warning banner instead of allowing direct entry. The banner points users to /inventory/settings to enable SME Mode or back to the purchase-order workflow.

Product Selection

The forms use a product search combobox and show the currently known stock for the selected product so the operator can see the existing balance before posting the new movement.

Purchase Orders

The current purchase-order experience is centered on the list page and the new-document page.

Purchase Order List

  • Search box: search by PO number or supplier.
  • Status filter: draft, pending, approved, ordered, partial, received, cancelled.
  • Visible columns: PO number, supplier, warehouse, order date, expected date, total, status, and actions.
  • Available actions from the list: open the document, edit draft POs, and cancel eligible POs.

Create Purchase Order

The new purchase-order form currently captures:

  • Order details: supplier, warehouse, order date, expected date, notes.
  • Line items: product, quantity, unit cost. The form auto-fills unit cost from the selected product when available.
  • Summary: running total and submit/cancel controls.

Status Handling

The backend routes support submit, approve, mark ordered, receive, and cancel transitions. The current frontend list page explicitly exposes view, edit for draft, and cancel where permitted.

Warehouse Transfers

The transfer workflow covers inter-warehouse movement requests and their lifecycle states.

Transfer List

  • Search field: search by transfer number.
  • Status filter: draft, pending, in_transit, completed, cancelled.
  • Visible columns: transfer number, source warehouse, destination warehouse, transfer date, expected date, status, creator, and actions.

Create Transfer

  • Transfer details: source warehouse, destination warehouse, transfer date, expected date, notes.
  • Validation: source and destination must be different.
  • Items: product plus quantity requested.
  • Product picker display: the product dropdown shows product name, SKU, and current stock quantity in the picker text.

Inventory Settings

The settings page is compact but important because it changes how manual stock work behaves.

SME Mode

SME Mode is presented as the most prominent setting. When it is enabled, direct stock entry becomes available. When it is disabled, users are steered away from direct entry and toward controlled purchase-order workflows.

Stock Behaviour Toggles

  • Allow Negative Stock
  • Track Batch Numbers
  • Track Expiry Dates
  • Require Adjustment Approval
  • Enable Barcode Scanning

SKU Generation

  • Auto-generate SKU

If Settings Fail to Load

The current page explicitly falls back to safe defaults and disables real saving if the inventory settings API returns an error. Resolve the backend issue first before relying on what you see in the form.

Operational Rules Behind the Screens

These rules come from the current backend implementation and directly affect how the UI should be used.

1. Warehouse Stock Is the Operational Stock Truth

Per-warehouse quantities live in stock_levels, and stock movement history lives in stock_movements. Treat warehouse stock as the operational source of truth for stock changes.

2. Stock Changes Flow Through One Service

The inventory backend documents InventoryService::adjustStock() as the only authorized path for stock mutations. This is why stock events in procurement, POS, ecommerce, and transfers must pass through controlled workflows instead of custom direct updates.

3. Low Stock and Out-of-Stock Summary Cards Use Dashboard Summary Counts

The dashboard summary counts are the card-level truth used in the current UI. Preview lists are previews, not the card source.

4. Financial-Impact Flows Must Stay Aligned with Accounting

For flows like POS sales and invoice posting, stock mutation and GL posting are designed to stay inside the same transaction boundary. Operational users do not manage that directly, but administrators and implementers should understand why uncontrolled stock shortcuts are risky.

5. Use Only the Screens That Match Your Workflow

  • Use /inventory/stock for review, quick modal actions, and movement history.
  • Use /inventory/operations when you need the dedicated manual entry forms.
  • Use purchase orders for formal vendor procurement.
  • Use transfers for inter-warehouse movement.
