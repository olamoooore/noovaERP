Financial Close — Developer Sequence Diagram

Developer-grade sequence view showing how a close review request flows from UI through application services, AI-OCR and AI analysis, policy gates, events/jobs, and canonical data stores. This sequence is intentionally implementation-oriented and maps to controller → service → policy → event → persistence patterns.

Developer Notes
Key rule
  • AI may enrich draft and review state.
  • AI must not become the accounting or reconciliation truth owner.
  • Final close authority remains canonical.
Suggested mapping
  • User / UI → controllers + requests
  • App Layer → FinancialClose* services
  • AI / OCR → AiOutputValidationService + FinancialCloseAiFindingService
  • Policy / Security → FinancialClosePolicyService + access control layer
Acronyms
  • AI = Artificial Intelligence
  • OCR = Optical Character Recognition
  • SoD = Segregation of Duties
  • SLA = Service Level Agreement
